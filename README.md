# FD2026 · Семинар 4 по Kotlin

## 1. Обновите свой форк на GitHub

Откройте **свой** `FD2026` и нажмите **Sync fork → Update branch**. Если написано, что форк уже актуален, ничего нажимать не нужно. Если форка ещё нет, откройте [репозиторий курса](https://github.com/TimofeyYA1/FD2026) и нажмите **Fork → Create fork**.

Если GitHub не даёт обновить форк из-за ваших коммитов, **не нажимайте Discard commits**. Скачайте или откройте свою копию по шагу 2, затем используйте подсказку под ним.

## 2. Скачайте форк или обновите копию на компьютере

**Ещё не клонировали?** На странице своего форка нажмите **Code → HTTPS**, скопируйте HTTPS-ссылку и передайте её команде `git clone`. В примере замените `ВАШ_ЛОГИН` на свой логин. Затем в IDEA откройте скачанную папку `FD2026` через **File → Open**.

```bash
git clone https://github.com/ВАШ_ЛОГИН/FD2026.git
```

**Уже клонировали?** Откройте **Terminal** в IDEA в корне проекта. Если есть незакоммиченные решения, сначала сделайте **Commit**. Затем:

```bash
git switch main
git pull --ff-only origin main
```

<details>
<summary>Не получилось обновить: как сохранить свои коммиты?</summary>

**`pull` сообщил `Not possible to fast-forward`.** В локальной `main` и в вашем форке есть разные коммиты. Объедините их без переписывания истории:

```bash
git pull --no-rebase origin main
```

Если Git сообщает о конфликте, разрешите его в IDEA или отмените слияние через `git merge --abort`. Если Git пишет, что общей истории нет, см. вариант ниже.

**`Sync fork` на GitHub не сработал.** После успешного `pull` из своего форка влейте обновления из репозитория курса:

```bash
git fetch https://github.com/TimofeyYA1/FD2026.git main
git merge --no-edit FETCH_HEAD
```

Если слияние прошло, выполните `git push origin main`. При конфликте можно отменить слияние через `git merge --abort`.

**Нет общей истории (`unrelated histories`).** Не трогайте старую `main`. Получите свежую версию курса в отдельной ветке:

```bash
git fetch https://github.com/TimofeyYA1/FD2026.git main
git switch -c seminar4-current FETCH_HEAD
```

Перенесите в неё только свои решения, сделайте **Commit**, затем `git push -u origin seminar4-current`. Если ветка уже существует, сначала проверьте, что в ней. `push --force` не нужен.

</details>

## 3. Откройте проект в IntelliJ IDEA

Откройте **корень** `FD2026`, где лежит `settings.gradle.kts`. Если IDEA предлагает импортировать Gradle, согласитесь. После обновления проекта нажмите **Gradle → Reload All Gradle Projects** и дождитесь окончания импорта.

**Какую Java выбрать?**

- Если у вас уже работает **JDK 26**, оставьте его. Второй JDK ставить не нужно.
- Если установлен только **JDK 21** или IDEA не запускает Gradle на 26, откройте **Settings → Build Tools → Gradle**, выберите **Wrapper** и поставьте **Gradle JVM: JDK 21**. Это версия для запуска Gradle; код и тесты всё равно используют **JDK 26**.

Нажмите **Reload All Gradle Projects**. Если Gradle не найдёт JDK 26, он попробует скачать его автоматически. Для первой сборки нужен интернет. Для запуска через ▶ проверьте, что в **File → Project Structure → Project → SDK** выбран **JDK 26**. Если IDEA его не видит или загрузка не удалась, выберите **Download JDK → 26**, затем снова перезагрузите Gradle. Если в панели Gradle отдельно подключены `System` или `lesson4/seminar`, отвяжите их и оставьте корневой проект.

В терминале настройка **Gradle JVM** из IDEA не применяется: Wrapper запускается через Java из `JAVA_HOME` или `PATH`. Проверьте её командой `./gradlew --version` (Windows: `.\gradlew.bat --version`). Устанавливать Gradle и Kotlin отдельно не нужно.

## 4. Запустите задачу и тесты

Откройте [Task01.kt](lesson4/seminar/tasks/Task01.kt) и нажмите ▶ рядом с `main()`. Пример задачи №1 выведет `Аня`. В задачах №5–8 сначала напишите решение, затем раскомментируйте пример в `main()`.

**Тесты в IDEA:** выберите `Task01Test` в списке запусков сверху и нажмите ▶. Или из корня проекта:

```powershell
# Windows: PowerShell
.\gradlew.bat :seminar-4:test --tests "*Task01Test"
```

```bash
# macOS / Linux
./gradlew :seminar-4:test --tests '*Task01Test'
```

Для задач 2–5 поменяйте номер теста. Для бонусов 6–9 замените `--tests ...` на `-Pbonus=06` (укажите нужный номер). Если тест пишет «задача пока не решена», он запустился, просто решение ещё не написано.

**Проверка на GitHub:** после **Commit → Push** в свой форк откройте **Actions → Семинар 4 → последний запуск → Summary**. Смотрите результат своей задачи, даже если весь запуск красный. Если Actions выключены, включите их на вкладке **Actions**. Для бонусов: **Дополнительные задачи → Run workflow**. Для классной работы PR не нужен.

[Домашнее задание](lesson4/homework/) будет опубликовано отдельно.
